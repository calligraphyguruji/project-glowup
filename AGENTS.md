**Project:** RepoDoctor AI (StackFit AI)

## 1. Project Purpose & Scope

RepoDoctor AI is an engineering intelligence web application that audits public GitHub repositories against domain expectations of top tech companies (Razorpay, Swiggy, Zerodha, Amazon). It identifies tutorial-clone anti-patterns, generates Before/After Mermaid.js architecture diagrams, and provides runnable concurrency test scripts.

## 4. Key Agent Operating Invariants

### 4.1. Repository Exploration & Modification Rules
- **Inspect Before Modifying:** Always view and understand existing code before applying edits.
- **Minimal, Surgical Changes:** Avoid rewriting entire files when a focused block edit suffices.
- **Never Break Working Builds:** Verify type checking and tests before completing tasks.
- **Never Commit Secrets:** Reject any modification that puts raw API keys, tokens, or `.env` files into version control.

### 4.2. Code Quality & Architecture Rules
- **No `any`:** Enforce strong typing across all API payloads and component props.
- **No Database / Redis (YAGNI):** The MVP is strictly stateless. Do not install Prisma, Mongoose, Supabase, or Redis unless an explicit ADR is approved.
- **Standard Library First:** Favor native Web Platform primitives (`fetch`, `crypto`, `URL`) over unnecessary npm packages.

### 4.3. Security & Safety Invariants
- **Never Execute Untrusted Code:** The server must never execute, compile, or evaluate code fetched from GitHub or generated by Gemini.
- **SSRF Guard:** Input URLs must strictly match `^https:\/\/github\.com\/[a-zA-Z0-9_.-]+\/[a-zA-Z0-9_.-]+$`. Outbound requests are limited to `https://api.github.com` and Google AI Studio.
- **Prompt Injection Defense:** Wrap untrusted repository code in structural delimiters (`<untrusted_source_code>`) and instruct the LLM to ignore embedded commands.

## 5. Development & Verification Commands

```bash

npm run dev

# Run TypeScript compiler check
npm run type-check   # (or npx tsc --noEmit)

# Run linter
npm run lint

# Run unit and integration tests
npm run test

# Production build verification
npm run build
```

## 6. Definition of Done for Any Agent Task

Before signaling task completion:
1. All changes compile cleanly without TypeScript or ESLint errors.
2. No mock/placeholder functions have been substituted for real features.
3. No secrets have been exposed or logged.
4. Edge cases (rate limits, 404s, invalid inputs) are handled gracefully.
5. Relevant documentation (`MEMORY.md`, `README.md`) is updated to reflect new states.
